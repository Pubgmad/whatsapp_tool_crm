A. INBOX ERROR REPORT
================================================================================

Exact error (screenshot)
- URL: /app/inbox
- UI: "Unable to load this page"
- Copy: "Please retry. Your sign-in has not been changed."
- Source: app/error.js (Next.js App Router segment error boundary)

Root cause
1. Hard load / refresh of /app/inbox bootstraps via GET /api/workspace/inbox
2. A dedicated slim route at app/api/workspace/inbox/route.js shadowed
   app/api/workspace/[section] and returned only contacts/conversations/pagination
3. Workspace shell then rendered state.setup.status / onboarding banner
4. state.setup was undefined → TypeError → app/error.js
5. Client navigation from Dashboard often worked because merge kept prior setup

Files affected / fixed
- app/api/workspace/inbox/route.js — now returns full loadState(..., view:'inbox')
  (setup, featureFlags, templates, teamMembers, conversations, etc.)
- components/workspace-app.js
  - emptyWorkspaceState.setup defaults + merge preserves setup
  - optional chaining on setup status/health
  - setup sub-routes (flows/media/numbers/…) load API view "setup"
- lib/workspace-inbox-loader.js — Agent listing clamp for all filters except mine/unassigned
- components/workspace-app.js — mounted previously orphaned CampaignPolicy UI
- tests/workspace-inbox-bootstrap.test.mjs — contract tests

Tests executed
- node --test tests/workspace-inbox-bootstrap.test.mjs (pass)
- node --test tests/workspace-inbox-filters.test.mjs (pass)

Final verification
- Hard refresh of /app/inbox must receive setup in JSON and render Shared inbox
- Disconnected WhatsApp shows onboarding banner, not a crash
- Deploy production_saas to crm.mathstrat-sites.com before expecting live fix

C. CONNECTOR EXPLANATION (no connector code changes in this pass)
================================================================================

Important: Ordinary businesses can use the WhatsApp CRM fully WITHOUT any ecommerce or CRM connector.
Connectors are optional add-ons for teams that already run Shopify/Woo/Salesforce/HubSpot.

| Connector | Business Purpose | Data Exchanged | CRM Use Case | Customer Setup Required | Current Implementation Status |
|---|---|---|---|---|---|
| Shopify | Connect an online store so WhatsApp can notify and follow up shoppers | Orders, checkouts, refunds, inventory checks, draft orders; webhook events | Order updates, abandoned-checkout recovery (when enabled), catalog/ops handoff | Shopify app OAuth (SHOPIFY_CLIENT_*), feature flag `connectors`; merchant Admin install | Fully implemented (OAuth + webhooks + drafts); privacy topics need Partner config |
| WooCommerce | Same idea for WordPress stores (Woo is a WP plugin; no Shopify-style SaaS OAuth) | Order created/updated; optional abandoned checkout via extension | Order WhatsApp updates; recovery if cart events are emitted | Store URL + signed webhook secret; point WC webhooks at /api/connectors/events/{id} | Fully implemented for signed webhooks; abandoned cart partial without WC extension |
| Salesforce | Sync sales CRM records with WhatsApp conversations | Contacts/Leads, Accounts, Opportunities (poll sync) | Sales agents message leads on WhatsApp while SF remains system of record | SALESFORCE_CLIENT_*, feature `crm_sync`, OAuth | Fully implemented (scheduled sync) |
| HubSpot | Marketing/sales CRM sync similar to Salesforce | Contacts (+ optional companies/deals) | Keep WhatsApp contacts aligned with HubSpot lifecycle | HUBSPOT_CLIENT_*, feature `crm_sync`, OAuth | Fully implemented (scheduled sync) |
| Google Calendar | Booking availability for WhatsApp Flows | Free/busy + optional event create | Appointment Flows book real calendar slots | GOOGLE_CLIENT_*, calendar mapping | Fully implemented |
| Workspace API + webhooks | Custom integrations without a named SaaS connector | Contacts/templates/send + outbound events | Zapier/Make/n8n recipes, custom backends | API keys + allowlisted webhook hosts | Fully implemented |
| Marketplace recipes (Zapier/Make/n8n/…) | Guided recipes over workspace webhooks | Same as workspace webhooks | No-code automation bridges | No native OAuth apps | UI/docs only |
| Dialogflow CX | Intent bot replies | NLU intents | Auto-reply bots | Dialogflow project + SA JSON | Fully implemented (AI path) |
| Razorpay (merchant) | Collect payments in WhatsApp commerce | Checkout / payment webhooks | Payment links / native order details (INR) | Merchant credentials | Fully implemented for merchant path |
| Platform Stripe/Razorpay | SaaS subscription billing | Plan charges | Tenant pays for the CRM itself | Platform secrets | Platform billing (not tenant CRM connector) |

Simple scenarios
- Shopify: Fashion brand sends “order shipped” and recovers abandoned carts on WhatsApp.
- WooCommerce: WordPress florist gets order.created webhooks and messages buyers.
- Salesforce: B2B sales team opens WhatsApp from a Lead synced into the shared inbox.
- HubSpot: Marketing qualifies leads in HubSpot; WhatsApp nurture continues in CRM.
- None: Clinic uses only Inbox + Templates + Broadcasts — no store or SF needed.
