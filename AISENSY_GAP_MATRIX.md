# WhatsApp SaaS production gap matrix

Audited 2026-10-04 against this local worktree and AiSensy's current official [feature index](https://aisensy.com/features), [Flows](https://aisensy.com/features/whatsapp-flows), [AI agents](https://aisensy.com/features/whatsapp-ai-agents), [live chat](https://aisensy.com/features/whatsapp-support), [payments](https://aisensy.com/features/whatsapp-payments), and [Ads Manager](https://aisensy.com/features/aisensy-meta-ads-manager) pages. This is a code audit, not a live-provider certification. "Implemented" below means a real code path exists, not that a connected Meta account or merchant has accepted it. AiSensy is a benchmark for outcomes; no branding or proprietary UI is reused.

The trace is UI -> route/service -> tenant data -> external call -> callback/worker -> updated UI. Code paths below identify the component/service; corresponding routes are in `app/api/`, migrations in `db/`, and scheduled work in `lib/jobs.js`. A missing stage is named explicitly. Status labels are **implemented but untested**, **partial**, **read-only**, or **missing**; no UI-only feature is counted as complete.

## Release priorities

**Critical:** Verify tenant isolation with a non-bypass database role; deploy/monitor the worker and webhook queues; harden opt-in/frequency enforcement; validate broadcast load/retries and native payments before selling those as ready. Never enable autonomous AI write actions without authorization and an operation ledger.

**Required:** Close the partial Flows, templates, Ads, commerce, integrations and reporting paths above; exercise live Meta/provider accounts; replace read-only or draft-only claims with precise UI wording. The booking-notice send now persists the outbound message and usage event in one transaction; this local fix has an isolated integration test.

**Advanced:** Autonomous AI, intent routing, per-screen Flow funnel, true in-chat webviews, external CRM object breadth, expanded ad objectives and optimization. These are product features beyond a Meta permission checkbox.

**Optional:** Provider-specific extras and wider channel connectors should follow proven customer need, not AiSensy's catalog alone.

## Evidence and limitations

The production build passed. The full isolated database suite passed 212 tests and skipped two deployed-app tests after its runner was made serial. An earlier parallel run had one Meta credit test-file failure; that test passed alone and in the serial full run. The targeted booking-notice integration test passed. None of these results proves Meta, Google, Shopify, Salesforce, HubSpot, Razorpay, OpenAI or real browser acceptance. The worktree contains uncommitted changes from earlier work. No live credentials were used. See `PRODUCTION_READINESS_MATRIX.md` for provider-specific release gates. This matrix reports observed code behavior and labels unexamined live behavior untested; it is not a claim of exhaustive penetration, load or UX certification.
